# Phase 2.4: Batch import

**Read first:** §3.5 (last paragraph), §4.5 ("Prompt caching", "Batch processing"), §6.1 ("Cache and batch") of `docs/plan.md`.
**Depends on:** 2.3.
**Branch:** `phase/2.4-batch`

## Goal

A hundred CVs go through endpoint 1 unattended, within the provider's quotas, and a killed worker
resumes without losing or repeating work.

## Build (commit units)

1. **`feat(api): accept large multi-file uploads on endpoint 1`**
   Streamed writes to disk, limits on file size and file count in configuration, and a clear error
   when a limit is exceeded. Progress per request: counts by document status.

2. **`feat(worker): make every job handler safe to repeat`**
   Audit each handler for a crash at every step: after the LLM call and before the write, between
   two writes, and so on. A repeated job must not create a duplicate assessment or pay for the
   same LLM call twice. Add the tests that prove it.

3. **`feat(worker): order jobs by position for prompt caching`**
   CVs of the same position are judged in sequence, so the stable prompt prefix is reused. Report
   the share of cached input tokens before and after.

4. **`feat(llm): add quota configuration and an optional batch api path`**
   Per-minute and per-day limits in configuration. Check the current Gemini Batch API
   documentation; if it fits re-scoring and eval runs, add it behind the same `LLMClient`
   interface. If it does not fit, say why and skip it.

5. **`test: add unattended import of 100 cvs`**
   With the fake client: 100 CVs, the worker killed and restarted in the middle, every assessment
   present exactly once at the end.

## Out of scope

n8n email intake (3.7 at the earliest), multiple workers.

## Done when

- [ ] 100 CVs imported with the fake client finish without intervention.
- [ ] Killing the worker with SIGKILL in the middle loses no job and creates no duplicate.
- [ ] A real run on the paid tier completes within the quotas with no unhandled 429 (show the dry run and wait for my confirmation).
- [ ] A document that fails three times ends as `failed` with a reason visible in the interface; the rest of the batch continues.
- [ ] Cached-token share and cost per CV for the batch are recorded in `docs/PROGRESS.md`.

## Traps

- "Exactly once" is not available; "at least once plus idempotent handlers" is. Design for the second.
- If you propose a second worker process, the in-process rate limiter from 1.2 is no longer enough. Raise it before building.
- A batch of real CVs must use the paid tier (§6.1). The test set here is synthetic.
