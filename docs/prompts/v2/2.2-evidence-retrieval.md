# Phase 2.2: Evidence retrieval and ablation

**Read first:** §1.1 ("Evidence: retrieval over the CV"), §4.1, §5.2 ("Evidence retrieval"), §6.2, §8 (last paragraph) of `docs/plan.md`.
**Depends on:** 2.1.
**Branch:** `phase/2.2-evidence-retrieval`

## Goal

Four retrieval variants over a candidate's chunks, measured against the gold quote spans, and a
recorded decision on which one stays in the pipeline.

## Build (commit units)

1. **`feat(search): add dense and lexical search over a candidate's chunks`**
   Dense: cosine distance in pgvector, filtered by `candidate_id` and `embedding_model`.
   Lexical: `tsvector` over normalized text with the `serbian` configuration, plus exact matching on `skills[]`.

2. **`feat(search): add hybrid search with reciprocal rank fusion`**
   RRF with k = 60 in one SQL query.

3. **`feat(search): add optional cross-encoder reranking`**
   `BAAI/bge-reranker-v2-m3` over the top 20–30 from fusion, returning the top 5. Loaded only in
   the worker and only when `RERANKER_MODEL` is set.

4. **`feat(eval): add evidence retrieval metrics and ablation`**
   Recall@5 and MRR per requirement, where a chunk counts as relevant if it overlaps the gold quote
   span. One table for dense, lexical, hybrid, and hybrid with reranking, broken down by language
   and script, with latency next to every quality number.

5. **`feat(pipeline): make build_context retrieval-aware`**
   `build_context()` can return the whole CV or the retrieved evidence per requirement, chosen by
   configuration. Measure judge accuracy in both modes on the dev split.

6. **`docs(eval): record ablation and retrieval decision`**

## Out of scope

Search across candidates (2.3). `pg_textsearch` BM25 and the two alternative embedding models are
optional extra rows in the ablation; add them only if I ask.

## Done when

- [ ] The ablation table exists in `docs/PROGRESS.md`.
- [ ] The chosen variant has recall@5 ≥ 0.9, and no script lags the best one by more than 5 points.
- [ ] A variant that does not raise the number is removed from the default pipeline, and the decision is recorded.
- [ ] Judge accuracy with retrieved context is recorded next to accuracy with the whole CV.
- [ ] Hybrid search is one SQL query, verified by reading the query log or the code path.

## Traps

- For a 2–3 page CV the whole text fits in the prompt, so retrieval may not help the judge at all
  (§8). That is a valid result. Record it; do not tune until retrieval "wins".
- CVs written without diacritics embed worse (§4.1). Report that subgroup separately.
- Do not run the reranker and Langfuse at the same time (§6.3). Turn the reranker on only for the ablation.
- Within one CV of about ten chunks the reranker has little to reorder (§4.1). Expect a small or zero gain there.
