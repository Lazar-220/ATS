# Phase 3.8: Red-team and v3 close

**Read first:** §4.3 (risk paragraph), §4.4 (all of it), §5.1 ("Injection" row), §5.2 ("Injection") of `docs/plan.md`; `docs/PROGRESS.md`.
**Depends on:** 3.7.
**Branch:** `phase/3.8-red-team`

## Goal

The share of successful attacks is measured for each defense layer, across every path that CV
text can take in v3, and v3 is closed with its numbers recorded.

## Build (commit units)

1. **`feat(eval): extend the attack set`**
   Grow the 20 pairs from 1.7 to the full set. Add attacks that target what v3 introduced: the
   resolver's tool results, the question text that reaches HR, an attempt to get CV text stored as
   a rule, and MCP tool results read by an external agent. Use the ResumeShield documents if they
   can be obtained under their license; if not, recreate their attack categories and say so.

2. **`feat(eval): add per-layer ablation`**
   Switches to disable each layer from §4.4 one at a time: extraction filtering, Unicode cleaning,
   channel separation, the hidden-skills rule, detection. Metric per configuration: the share of
   attacks that change a verdict or a score.

3. **`feat(guardrails): add optional prompt guard classifier`** (only if I confirm)
   Llama Prompt Guard 2 as an optional detector. Measure it on Serbian Latin, Cyrillic and English
   before trusting it; report false positives on clean CVs.

4. **`docs: write the red-team report and close v3`**
   The per-layer table, the attacks that still succeed with an explanation, and the final v3
   numbers. Use the phase-verifier subagent on every v3 phase prompt. Tag `v3.0.0` if I confirm.

## Out of scope

Counterfactual fairness tests, real-data evaluation, multi-tenant (all listed under "After v3" in §7).

## Done when

- [ ] The share of successful attacks is measured per defense layer and recorded.
- [ ] No attack makes CV text into a rule, and none reaches HR as free text in a question (tests).
- [ ] Every attack that still changes a verdict or a score is listed with an explanation and a proposed fix.
- [ ] `docs/PROGRESS.md` holds the closing numbers for v3, and every "Carried over" row is closed or listed.

## Traps

- The ablation disables defenses. The switches must exist only in the eval harness, never in
  application configuration.
- ResumeShield is small and synthetic (§4.4). Treat it as red-team material, not as proof.
- There is no published data on Prompt Guard for Serbian (§4.4). A detector that flags half the
  clean Cyrillic CVs is worse than none.
- Attack files are test data. Keep them under `eval/`, and never let one into the smoke cache that CI trusts.
