# Phase 3.7: MCP server and notifications

**Read first:** §4.3, §4.5 (n8n row and the license note) of `docs/plan.md`, and the current
documentation of the `mcp` Python SDK version 2.
**Depends on:** 3.6.
**Branch:** `phase/3.7-mcp-notifications`

## Goal

A second interface over the same service layer: an MCP client can ask who the top candidates are
and why, and answer an open question. HR is notified when a new question appears.

## Build (commit units)

1. **`feat(mcp): add mcp server with read tools`**
   `list_positions`, `top_candidates`, `get_assessment`, `explain_verdict`, `list_open_questions`.
   Each calls a service function; none contains logic of its own. Results are structured fields,
   with quotes marked as data. Served over stdio and Streamable HTTP. `make mcp`.

2. **`feat(mcp): add search_candidates and answer_question`**
   `search_candidates` is endpoint 2; `answer_question` is endpoint 3 and is the only tool that writes.

3. **`docs: connect the mcp server to claude code`**
   The exact command to register the server, checked against the current Claude Code
   documentation, and three example questions with the answers you got.

4. **`feat(notify): emit a webhook when a question is created`**
   Sent after the transaction commits, with retry, and safe to deliver twice. The URL is in
   configuration; with no URL nothing is sent.

5. **`feat(infra): add optional n8n service and exported workflow`**
   n8n behind a Compose profile, and the workflow that receives the webhook and notifies HR,
   exported as JSON in the repository.

## Out of scope

CV intake from email through n8n (after v3). Authentication on the MCP server beyond local use;
say what a hosted deployment would need.

## Done when

- [ ] From an MCP client, I get the top 5 for a position with a rationale, and I answer an open question.
- [ ] The answer given through MCP triggers the same re-judging as endpoint 3.
- [ ] A test proves that only `answer_question` can change data.
- [ ] Creating a question delivers one notification; a retried delivery does not notify twice.
- [ ] With n8n stopped and no webhook URL, everything else works.

## Traps

- A tool result carries CV text into an agent that has broader privileges than the judge (§4.3).
  Return structured fields, mark quotes as data, and never return raw CV text as a free-form string.
- MCP does not sit between the orchestrator and the resolver tools. Those stay direct function calls (§4.3).
- n8n, Langfuse and the reranker do not fit in memory together (§6.3). Check `docker stats` before starting n8n.
- n8n's license allows internal use and self-hosting; it is not OSI open source (§4.5). Note it in the README.
