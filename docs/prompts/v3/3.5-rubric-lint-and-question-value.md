# Phase 3.5: Rubric lint and question value

**Read first:** §1.3 (last paragraph), §2.4 ("Position setup" step 3), §3.4 (last two bullets), §5.1 ("3. Loop" row), §5.2 (the five question metrics) of `docs/plan.md`.
**Depends on:** 3.4.
**Branch:** `phase/3.5-question-value`

## Goal

Fewer and better questions: likely ambiguities are raised once when a position is created, and
during scoring a question is asked only if its answer can change something that matters.

## Build (commit units)

1. **`feat(pipeline): list likely ambiguities when a position is created`**
   One LLM call at position setup lists situations the requirements leave undefined (practice
   counted as tenure, a bootcamp counted as a degree). They become open questions for HR up front,
   through the same deduplication and the same limit of five as in 3.3.

2. **`feat(services): ask only when the answer can change the outcome`**
   Code decides, not the model: compute the candidate's score under the best and the worst answer.
   Ask only if the range can change membership in the shortlist or the status of a mandatory
   requirement. Otherwise apply `partial` and record the assumption.

3. **`feat(eval): add gold ambiguities and the five question metrics`**
   30–40 cases of an undefined rule, each with the expected action and question topic, including
   the same case in another language and script. Metrics: necessity, coverage, duplicates, impact, reuse.

4. **`docs(eval): record question metrics`**

## Out of scope

Rule retrieval, company-level rules, notifications (3.7).

## Done when

- [ ] Question necessity ≥ 0.8.
- [ ] Duplicates per position: 0.
- [ ] Coverage, impact and reuse are measured and recorded.
- [ ] A question whose every answer leaves the shortlist and all mandatory statuses unchanged is not asked (test).
- [ ] The questions raised at position creation appear in the inbox before any CV is scored.

## Traps

- "Shortlist" needs a definition the code can compute: propose it (for example, the top K of the
  current ranking for the position) and confirm it with me.
- Up-front questions compete for the same limit of five. Decide the priority between up-front and
  scoring-time questions, and record it.
- The ambiguity call must not invent requirements. It lists gaps in the existing ones.
