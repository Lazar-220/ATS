# Phase 3.6: LangGraph port

**Read first:** §3.6 (all of it) of `docs/plan.md`, and the current LangGraph documentation for
`PostgresSaver`, `interrupt()`, `Command(resume=...)` and `create_agent`.
**Depends on:** 3.5.
**Branch:** `phase/3.6-langgraph-port`

## Goal

The same flow, implemented a second time on LangGraph, selected by configuration, passing the same
scenario tests. The result is a working alternative and a written comparison.

## Build (commit units)

1. **`feat(langgraph): add graph with one thread per assessment`**
   States become nodes. `PostgresSaver` from `langgraph-checkpoint-postgres` stores checkpoints;
   its `setup()` creates its own tables, kept apart from the application's migrations.

2. **`feat(langgraph): pause on questions with interrupt and resume from question_waiter`**
   The `ask_hr` node calls `interrupt()`. An answer resumes each waiting thread with `Command(resume=...)`.
   Question creation is its own node or an upsert, so that re-execution on resume creates nothing twice.

3. **`feat(langgraph): port the resolver to create_agent`**
   The same seven tools and the same Gemini model through `langchain-google-genai`. The same budgets.

4. **`feat(worker): select the orchestrator by configuration`**
   `ORCHESTRATOR=manual|langgraph`. Both run behind the same service interface.

5. **`docs: compare the two implementations`**
   Lines of code, what the checkpointer and interrupt replaced, what stayed your job (the data
   model: one question waking N assessments, rule versions, re-judging), latency, and how each is debugged.

## Out of scope

Removing the manual implementation. LangChain or LlamaIndex for retrieval (the plan excludes them).

## Done when

- [ ] The four scenario tests from 3.3 and the budget tests from 3.4 pass with `ORCHESTRATOR=langgraph`.
- [ ] The same tests still pass with `ORCHESTRATOR=manual`.
- [ ] A test proves that resuming a thread does not create a second question.
- [ ] The comparison is written in `docs/` and summarized in `docs/PROGRESS.md`.

## Traps

- On resume, the interrupted node runs again from its beginning (§3.6). Everything before
  `interrupt()` must be idempotent. This is the trap the phase exists to teach; write the failing test first.
- These libraries change quickly. Verify every signature against the current documentation and
  record the versions you installed.
- This is the first phase that adds LangChain packages. Keep them out of the retrieval and judge paths.
- If the full port proves too large for one session, port the resolver first (§3.6, last line) and stop at a commit boundary.
