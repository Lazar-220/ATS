# Phase 1.1b: Ingest (endpoint 1, text extraction, script normalization)

**Read first:** §1.1, §2.0, §2.2 (last paragraph on Serbian), §2.4 ("Per CV" steps 1–2), §4.2 of `docs/plan.md`.
**Depends on:** 1.1a.
**Branch:** `phase/1.1b-ingest`

## Goal

`POST /rankings` accepts a posting PDF and CV PDFs, returns 202, and the worker turns each PDF
into clean text in the database. No LLM yet: this phase ends at stored `raw_text`.

## Build (commit units)

1. **`feat(pipeline): extract pdf text and reject scanned pdfs`**
   Text extraction with PyMuPDF, page by page. A PDF with too few characters per page is a scan:
   it is rejected with a clear message and the document gets a status that says why.
   Write the extraction as a sequence of cleaning steps, so phase 1.7 can add hidden-text removal
   without rewriting it.

2. **`feat(pipeline): detect language and script, normalize serbian text`**
   Language with `lingua-language-detector`, limited to Serbian, Croatian, Bosnian and English;
   the first three count as one class. Script (Latin, Cyrillic, mixed) from Unicode ranges.
   `normalize_for_lexical(text)`: Cyrillic to Latin with `cyrtranslit`, lowercase, `đ` to `dj`,
   diacritics stripped. This function is for comparison and lexical search only; the stored
   `raw_text` stays in the original script.

3. **`feat(api): add POST /rankings that returns 202 and enqueues ingest jobs`**
   Multipart upload: one posting PDF, one or more CV PDFs. Validate that each file is a PDF.
   Store files under `UPLOAD_DIR` by `sha256`. The posting's `sha256` finds or creates the
   `job_position` (status `unconfirmed`, `rubric_version` 1). A CV whose `sha256` already exists
   reuses its `document`. Create the `ranking_request` and `request_candidate` rows, enqueue one
   ingest job per new document, and return 202 with `request_id`.

4. **`feat(worker): add ingest handler that stores raw text, language, script and flags`**
   The handler runs extraction and detection and writes `raw_text`, `lang`, `script` and the
   status to `document`. A rejected scan fails the document, not the whole request.

5. **`feat(api): add GET /rankings/{request_id} status endpoint`**
   Read-only: request status and, per document, its status and rejection message.
   Add a `curl` example for both endpoints to `docs/SETUP.md`.

## Out of scope

Requirement extraction (1.2), masking and CV parsing (1.4a), hidden-text and Unicode cleaning (1.7),
OCR (after v3).

## Done when

- [ ] Three test PDFs (Serbian Latin, Serbian Cyrillic, English) produce clean `raw_text` in the
      database with the right `lang` and `script`.
- [ ] A scanned (image-only) PDF is rejected with a readable message, visible through the status endpoint.
- [ ] `POST /rankings` returns 202 with a `request_id`, and the results appear in the database
      without any further call.
- [ ] Uploading the same CV twice creates one `document` and no second ingest job.
- [ ] Uploading the same posting twice resolves to the same `job_position`.
- [ ] `normalize_for_lexical` maps "вођење", "vođenje" and "vodjenje" to the same string (unit test).

## Traps

- Build the test PDFs in the test suite with PyMuPDF; do not commit binary fixtures unless they are tiny.
  Check that the Cyrillic fixture really contains Cyrillic after a round trip through extraction.
- Two-column layouts scramble reading order. Do not try to fix that here; §2.2 handles it through
  structured extraction in 1.4a. Add one two-column fixture and record what the extracted text looks like.
- The language detector labels Serbian Latin as Croatian or Bosnian (§4.2). That is expected; the class is shared.
