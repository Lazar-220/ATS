# Phase 1.4a: Masking, CV parsing, tenure

**Read first:** §2.2, §2.4 ("Per CV" steps 3–4), §4.2, §6.1 ("Thinking") of `docs/plan.md`.
**Depends on:** 1.3.
**Branch:** `phase/1.4a-cv-parsing`

## Goal

Each CV becomes masked text and a structured JSON with dated items, and code computes the months
of experience. The judge in 1.4b works from these.

The plan's phase table does not assign masking to a phase. It has to exist before the first LLM
call that sees a CV, so it is built here.

## Build (commit units)

1. **`feat(pipeline): mask personal data with a reversible span map`**
   Replace name, email, phone and address with placeholders. Originals go to the `candidate` table;
   `document` keeps both `raw_text` and the masked text. Keep a span map between masked and raw
   offsets, so a quote found in masked text can be located and highlighted in `raw_text`.
   Email and phone by pattern. For name and address, propose an approach that needs no LLM call and
   show me its limits before building it.

2. **`feat(pipeline): add cv triage and structured parsing`**
   One LLM call on masked text: is this a CV; structured JSON with experience, education, skills,
   certificates, languages and projects; a suspected-injection flag. Every item carries a verbatim
   snippet of its source text and, where they exist, start and end dates. Prompt version 1 as a file.
   `thinking_level` minimal. A document that is not a CV is flagged and gets no assessment;
   triage never rejects a candidate because of content.

3. **`feat(pipeline): locate item snippets and flag low coverage`**
   Code finds each snippet's position in the text. If the items cover less than 85% of the text,
   flag the document. The paragraph fallback from §2.2 belongs to chunking in 2.1; here only the flag.

4. **`feat(pipeline): compute tenure with overlap merging`**
   Months per item and total tenure with overlapping periods merged. "Present" resolves against an
   injected clock. Handle year-only dates and missing end dates explicitly. The results are stored
   with the parsed JSON as ready-made facts.

5. **`feat(worker): wire masking and parsing into ingest; add masking leak metric`**
   The ingest job now runs masking, parsing, snippet location and tenure. The eval harness gains a
   masking metric: the share of golden CVs whose masked text still contains the profile's name,
   email or phone.

## Out of scope

The judge and the score (1.4b). Chunks, embeddings and the skills alias table (2.1).

## Done when

- [ ] A test proves the LLM receives only masked text: the fake client's recorded prompt contains
      none of the candidate's name, email or phone.
- [ ] Masking leak rate on the golden set: 0% for email and phone; the rate for names is measured
      and recorded in `docs/PROGRESS.md`, with the leaked cases listed.
- [ ] Tenure unit tests: 2019-03 to 2023-06 is 51 months; two overlapping jobs are not counted twice;
      an open-ended job runs to the injected "today".
- [ ] A non-CV document is flagged and produces no assessment.
- [ ] A document whose items cover less than 85% of the text carries the coverage flag.
- [ ] Parsed JSON, masked text and computed months are stored for every golden CV in the dev split
      (show the dry run before calling the real model).

## Traps

- The judge will quote from masked text. A quote that includes a placeholder must still be
  checkable; the span map is what makes that possible. Write the test for it now.
- Two-column PDFs scramble text order. Verbatim snippets are how item boundaries survive that (§2.2);
  check the two-column golden CVs specifically.
- Date arithmetic belongs to code. The parsing prompt returns dates as written in a fixed format,
  never durations.
