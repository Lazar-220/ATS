# Phase 1.7: Guardrails and CI

**Read first:** §4.4 (the whole table and the two paragraphs after it), §5.1 ("Injection" row), §5.4 (CI bullet) of `docs/plan.md`.
**Depends on:** 1.6.
**Branch:** `phase/1.7-guardrails-ci`

## Goal

A CV cannot raise its own score through hidden text or instructions, this is measured on a
red-team set, and CI stops a regression from being merged.

## Build (commit units)

1. **`feat(pipeline): remove hidden text during extraction`**
   Drop a span whose color is close to the background, whose font is below 4 pt, that lies outside
   the page, or that uses an invisible render mode. Additional check: the span's region on the
   rendered page is a single color. Removed text is logged and the document gets a flag for HR.
   The flag never rejects a candidate.

2. **`feat(pipeline): clean invisible unicode and flag mixed-script words`**
   Delete characters of categories Cf, Co and Cn. A word that mixes Cyrillic and Latin letters is
   a homoglyph signal: flag it, do not alter it.

3. **`feat(pipeline): harden channel separation and add injection detection`**
   Confirm the fenced data block and the inert-content system message from 1.4b; make sure CV text
   cannot close the fence. A skill that appears only in a skills list, with no confirmation in
   experience, gives at most `partial`. Pattern-based detection of instruction-like text in Serbian
   and English sets a flag for HR.

4. **`feat(eval): add red-team set and make eval-redteam`**
   Twenty pairs: a clean CV and the same CV with one attack. Cover white text, tiny font, off-page
   text, invisible render mode, zero-width characters, a visible instruction, and a hidden skills
   list; in Serbian Latin, Cyrillic and English. Metric: the share of attacks that change a verdict or the score.

5. **`ci: add github actions workflow`**
   Jobs: ruff, pyright, unit tests, integration tests against a Postgres service with pgvector, web
   typecheck and lint, and a smoke eval of 20 cases served entirely from a committed LLM cache.
   The smoke eval fails the build when accuracy or quote validity drops below a threshold.

## Out of scope

The Llama Prompt Guard 2 classifier (optional in the plan; revisit in 3.8 with a measurement on Serbian).
The full attack set and per-layer ablation (3.8).

## Done when

- [ ] A test PDF with the five kinds of hidden text yields none of it in `raw_text`, and each removal is logged.
- [ ] No attack in the red-team set changes a verdict or the score; any exception is listed and explained in `docs/PROGRESS.md`.
- [ ] The CI workflow passes on a clean branch.
- [ ] CI fails when the smoke eval fails: demonstrated by raising the threshold above the current value on a throwaway branch.
- [ ] The smoke cache contains synthetic data only, and CI makes no real LLM call.

## Traps

- Plain `page.get_text()` returns white, tiny and invisible text as normal text (§4.4). Use the span-level
  color and size, the text trace for the render mode, and the render check together.
- Hidden text is usually a hidden skills list, not an instruction (§4.4). Test that case first.
- Deleting Cf characters must not break legitimate text. Run the whole golden set through the cleaner
  and confirm that `raw_text` of clean CVs is unchanged apart from the removed characters.
- Pushing to GitHub needs my approval. Ask before the first push and tell me which remote you will use.
