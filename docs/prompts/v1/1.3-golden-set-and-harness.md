# Phase 1.3: Golden set and eval harness

**Read first:** all of §5 of `docs/plan.md` (5.1 to 5.4).
**Depends on:** 1.2.
**Branch:** `phase/1.3-golden-set`

## Goal

A golden dataset whose labels are known by construction, and one command that turns it into a
metrics table. Everything after this phase is measured against it.

## Build (commit units)

1. **`feat(eval): add golden set layout, schemas and loaders`**
   Under `eval/golden/`: positions (posting source text, posting PDF, gold requirements), profiles,
   CVs (source text and PDF), labels as JSONL (one verdict and one quote span per CV–requirement
   pair, plus relevance 0–3 per CV–position pair), hard cases, and a fixed dev 70% / test 30% split
   stratified by position and language. Pydantic schemas and loaders with validation.

2. **`feat(eval): add pdf renderer for single- and two-column cvs`**
   Render a CV source text to PDF in two templates, with correct Latin diacritics and Cyrillic.
   Prefer PyMuPDF, which is already a dependency. Test that the rendered text survives a round trip
   through the extraction from 1.1b.

3. **`feat(eval): add mini golden set`**
   Two positions and eight CVs, complete with profiles, labels and split. Order of work: profile
   first (for each requirement the verdict and the fact that proves it), then the CV written from
   the profile. You write the profiles and the CV texts yourself, as files. That keeps the
   generator a different model from the judge and costs no Gemini quota.

4. **`feat(eval): add harness and make eval`**
   `make eval VARIANT=A SPLIT=dev LIMIT=n`: loads the JSONL, calls the pipeline functions directly
   (not over HTTP), computes the metrics, prints a table, and writes a result file with
   `pipeline_version` (git commit plus prompt versions). Metrics now: requirement extraction
   precision, recall, F1 and label accuracy; verdict accuracy, macro-F1, confusion matrix, weighted
   kappa; share of verdicts whose quote exists in the CV. The judge does not exist yet, so run the
   verdict metrics against a stub judge to prove the plumbing. `--dry-run` prints the number of LLM
   calls and the estimated cost without calling anything.

5. **`feat(eval): add full golden set`** (several commits, one per batch)
   Six positions with deliberate overlap, each with 8–12 requirements. 60–90 CVs with the
   distribution from §5.1: 40% Serbian Latin (half of those without diacritics), 20% Cyrillic,
   30% English, 10% mixed; both PDF templates. 15–20 hand-written hard cases from the list in §5.1.
   Work in batches of about ten CVs and commit each batch. If the session runs long, stop at a
   batch boundary and say where to resume.

6. **`docs(eval): add review sheet for the manual 20% sample`**
   A sheet listing a random 20% sample (fixed seed) with, per CV, the profile's claims next to the
   places in the CV that should prove them. I do the check by hand; you prepare it.

## Out of scope

Real CVs. The loop cases, injection pairs and ranking metrics from §5.1 and §5.2 arrive with the
phases that need them (1.7, 2.2, 2.3, 3.1).

## Done when

- [ ] `make eval VARIANT=A SPLIT=dev` prints a metrics table and writes a result file.
- [ ] Requirement extraction F1 on the six golden postings is measured with the real model
      (six calls; show the dry run first) and recorded in `docs/PROGRESS.md`. Target ≥ 0.85.
- [ ] The split is reproducible: the same seed gives the same assignment.
- [ ] Every label references an existing CV, position and requirement (validation test).
- [ ] The review sheet exists and I have confirmed the sample, or listed the CVs to regenerate.

## Traps

- Matching extracted requirements to gold requirements must be deterministic and explainable, with
  no LLM in the metric. Propose the matching rule and show me three borderline examples before relying on it.
- A gold quote span must be a verbatim substring of the CV source text. Validate it in the loader.
- Synthetic CVs are cleaner than real ones (§5.1). Make the hard cases hard: implicit evidence,
  overlapping periods, a skill that appears only in a list.
- Tune prompts on the dev split only. The test split is for published numbers.
