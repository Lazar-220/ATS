# Phase 1.8: v1 gate

**Read first:** §7 (the gate diagram, "v1", "Refactor before v2"), §5.2, §5.3 (last two paragraphs) of `docs/plan.md`; `docs/PROGRESS.md`.
**Depends on:** 1.7.
**Branch:** `phase/1.8-v1-gate`

## Goal

Decide, with numbers, whether v1 is done. No new features in this phase.

## Do

1. **Check carried-over items.** Every row under "Carried over" in `docs/PROGRESS.md` is either closed or listed in the report.

2. **Run the full eval.** Variant A on the test split, three runs. Show `--dry-run` first and wait
   for my confirmation. Record per run and as a mean: verdict accuracy, macro-F1, weighted kappa,
   the share of verdicts with a verified quote, requirement extraction F1, masking leak rate,
   red-team success rate, cost per CV, p50 and p95 per step. Break verdict accuracy down by language and script.

3. **Review failures.** Use the eval-failure-reviewer subagent on the test-split failures. Do not
   change prompts in response; record the causes.

4. **Verify the refactors that v2 depends on.** The judge gets its input only through
   `build_context()` and `ContextPack`. Every stored CV has `raw_text`, masked text and parsed JSON,
   so v2 can chunk and embed it without a re-upload.

5. **Verify independently.** Use the phase-verifier subagent against each v1 phase prompt's "Done when" list.

6. **`docs: record v1 gate results`**, then, only if the gate passes and I confirm, tag `v1.0.0`.

## The gate

- Verdict accuracy is measured (target ≥ 80% on the test split).
- Every quote shown as evidence exists in the CV.

## Done when

- [ ] The numbers above are in `docs/PROGRESS.md` with `pipeline_version` and run count.
- [ ] The gate is stated as PASSED or NOT PASSED, with the evidence.
- [ ] If NOT PASSED: a ranked list of fixes, each tied to a failure cause and an expected gain. No v2 work starts.
- [ ] If PASSED and confirmed: `v1.0.0` is tagged and the README describes what v1 does and how to run it.

## Traps

- With about 250 verdicts in the test split, a difference of three percentage points between runs is
  probably noise (§5.3). Report the spread across the three runs.
- A threshold that is narrowly missed is still missed. The plan says: stay in the same version and fix the pipeline.
