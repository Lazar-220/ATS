# Phase 1.5: Interface

**Read first:** §1.1 (last line), §2.0, §2.4 (ordering in "Per endpoint 2 call" step 3), §6.3 ("Frontend") of `docs/plan.md`.
**Depends on:** 1.4b.
**Branch:** `phase/1.5-interface`

## Goal

HR can upload, see the ranked list per position, and check every verdict against the CV text
without opening the PDF.

## Build (commit units)

1. **`feat(web): add typed api client and query hooks`**
   Types that mirror the API schemas, one client module, TanStack Query hooks. Prefer generating
   the types from the OpenAPI schema over writing them by hand; say which tool you would add.

2. **`feat(web): add upload flow for endpoint 1`**
   A form for one posting PDF and several CV PDFs, then progress by polling the request status.
   Rejected documents show their message.

3. **`feat(web): add ranked list per position`**
   TanStack Table: candidate, score, failed-mandatory flag, assessment status, and the
   "rubric unconfirmed" label. Order as the API returns it: candidates without a failed mandatory
   requirement first, then by score.

4. **`feat(web): add assessment view with highlighted quotes`**
   Requirements on one side with verdict, rationale and flags; the CV text on the other with the
   quote highlighted from the character offsets. Selecting a requirement scrolls to its quote.
   A verdict whose quote failed the check is marked as unverified and shows no highlight.

5. **`feat(web): add navigation, empty, loading and error states`**
   Routes between positions, requirements (the screen from 1.2), ranking and assessment.

## Out of scope

Authentication, multi-tenant, the open-questions inbox (3.3), the search screen for endpoint 2 (2.3).

## Done when

- [ ] From a clean database, I can upload a posting and CVs in the browser and reach a ranked list with no other tool.
- [ ] Every verdict can be checked without opening the PDF: its quote is highlighted in the CV text.
- [ ] HR sees the candidate's real name in the interface, while the API calls to the LLM still carry only masked text.
- [ ] `make check` includes the web typecheck and lint and passes.
- [ ] Screenshots or a short description of each screen are in the phase report.

## Traps

- Render CV text as text. Never inject it as HTML: a CV is untrusted input (§4.4).
- Offsets refer to `raw_text`. Normalizing or trimming the text on the client breaks the highlight.
- Keep the design plain and consistent. No component library unless you can say what it saves.
